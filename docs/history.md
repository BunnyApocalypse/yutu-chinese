**To know** (lessons that hold across sessions):

- Pictures for a decision: the atlas with `SIZES=` and `TRY_CSS=` for a look (`scripts/ux-atlas.js`), or a small script on the browser tests' harness for anything else. Put them in `local/`, delete them once the point is built, and always give the picture's path. The owner chooses from pictures side by side.
- **A background session inside a worktree can't run git in the main checkout**, nor write files there: to `git pull` the owner's checkout, leave the worktree first (ExitWorktree, keep), and copy files for `local/` across with `cp`.
- **A new worktree needs a real copy of `node_modules`** (`cp -a`), not a link: Vite won't serve files from outside the project, and the Anki import tests fail. It also needs `node scripts/copy-char-data.js` and `node scripts/copy-audio.js` before a picture script; the test command does that by itself.
- **Running commands in a worktree:** a command that changes directory, chains steps around version control, or runs `sed` with a computed program is refused as unverifiable; write scripts to files and run plain separate commands.
- **`reloadApp` in the harness switches the page to both scripts, mostly traditional**, even after `startBrowsers(..., { keepWelcome: true })`: a picture script that reloads shows traditional forms whatever the app's default.
- Two browser tests fail now and then in a full run only (`tests/browser/CLAUDE.md`): run the file alone before suspecting a change.
- A label beside a heading must fit on a 360px phone: measure it in the page rather than guess.
- Rename by pattern only at exact places, then compare strings and comments with the original.
- Files in `~/Downloads` (the old test files, tester 3's `notes.txt`, now in `local/testing/`) are the owner's to delete.

- A raw input recording replays outside the browser (`local/ting-replay.mjs`), which shows a refused stroke's cause at once. The owner's `npm run dev` runs in the main checkout, so work in a worktree is tried from there or brought into `main` first.
- Hanzi Writer's tolerances are fixed distances in the data's units, so anything judged on stroke data moved into the frame must scale with it (`isJoinable`'s `scale`).
- In a copy of the raw input shown smaller, the strokes must lose `vector-effect: non-scaling-stroke` or they look swollen (`quiz.drawing()`). The meaning line's cut-off (`clamp.js`) can cut only a part marked `data-clamp`.
- CC-CEDICT gives some entries a Taiwan reading that is another entry's mainland one (打): match the mainland reading first.
- A test can hold IndexedDB reads back by keeping a writing transaction open on the store (`startup.browser.js`). A made-up `PointerEvent` has no pointer to capture: a tone card tapped while it asks needs real mouse input (`Input.dispatchMouseEvent`).
- **Never wait on a process with `until ! pgrep -f <name>`** (the waiting shell's own command holds the name); `pkill -f` with a path that is also in your own command line kills that command.
- Writing notes: a gather must skip words and characters declined in earlier batches, or they come back; a judge reading the whole note as a native-level reader catches what matters more than checking each meaning against a dictionary; sending fixes back to the writer costs little, a fresh fixer nearly as much as writing.

- **At most, a pronunciation deck** (the owner, 2026-10-30, when leaving listening practice out): something like helq's "Pinyin for beginners" Anki deck (https://github.com/helq/pinyin-beginners-anki-deck, on AnkiWeb as 854183352), which teaches how Chinese syllables sound. It has four parts: initials, finals, similar-sounding syllables (pick which of two or three you heard), and tones. Each card has pinyin, zhuyin and IPA and three recordings by different native speakers. **Its code and data are BSD-3-Clause, which can be used with GPL; its recordings cannot be used:** they are downloaded separately, collected from eight teaching sites, with no license ("I don't own any of the recordings"). Built in the app, it would use our own syllables (`data/audio-cmn/syllables`, every syllable in four tones, CC BY-SA), but they come from one speaker, where the deck plays three. Not planned; how it would fit (a deck of its own kind, or Free practice) is open.

**Decided against** (so they aren't proposed again):

- **"Show more" past a list's first 200 words** (the owner, 2026-10-30): not needed; the rest are reached by searching (`MAX_ROWS`, `docs/words.md`).
- **Listening practice** (the owner, 2026-10-30, after a write-up of options): no listening cards, tones by ear, dictation, sentence audio for listening, or longer listening; that is left to podcasts, graded audio and tutors. Hearing a word on its cards and page stays as it is (`docs/word-page.md`, "Sound"). The one exception that may come is a pronunciation deck (under "Nice to have").

- **Anki sync** (the owner, 2026-10-15): syncing through AnkiWeb is against its terms and would need a server; the self-hosted server and AnkiConnect are a poor fit, since Anki has no writing check.
- **A handwriting-style font (楷体)** for the characters being learned (the owner, 2026-10-17): the gap between printed and handwritten shapes "represents the realities of handwriting vs computer fonts in the sinosphere"; the writing area teaches the written shapes, the rest stays in the device's font.
- **Separating a word's facts from what to do to its cards** in its panel (tester 2's idea): the owner often wants both at once, as with a leech.
- Someone who skips the introduction starts with no words (2026-10-16); since 2026-10-19 Review offers them a level to start with.
- **Anything inside the introduction for trying the app first** (the owner, 2026-10-19, after trying a draft with "Try writing a character" on its first screen): it interrupts the introduction; help for newcomers comes after it.
