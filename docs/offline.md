## Offline use and deployment (the PWA)

Built on 2026-10-13. The owner chose: all stroke data saved on the device, and automatic deployment.

- **Where it runs: two copies at one site** (since 2026-10-13, for testers; the owner's decision). `.github/workflows/deploy.yml` builds both whenever either branch is pushed (after `npm test` on each; the browser tests are not run there):
  - the **stable** copy, from the `stable` branch, at https://bunnyapocalypse.github.io/yutu-chinese/. This is what people use, the owner's own data included.
  - the **test** copy, from `main`, at https://bunnyapocalypse.github.io/yutu-chinese/test/. Everything pushed to `main` is live there within minutes.
  - **To release what is on `main`:** `git push origin main:stable`, then `gh workflow run deploy.yml --ref main`. Ask the owner first: that is what reaches testers. The second command is needed because the repository's `github-pages` environment only lets `main` publish: a run started by the push to `stable` is turned away ("not allowed to deploy due to environment protection rules", seen at the first push on 2026-10-13), so the workflow is only started by `main` or by hand, and builds both branches whichever way.
  - **The test copy is told apart by `VITE_CHANNEL=test` at build time** (`__CHANNEL__`, `vite.config.js`). A browser keeps one set of databases and caches for the whole site, whatever the folder, so the test copy uses a database of its own name (`hanzi-trainer-test`, `src/db.js`) and its own store of app files (`test-app-…`, `src/serviceWorker.js`), and the stable copy's service worker leaves requests under `test/` alone. It is named "(test)" in its title, its version line and its home-screen name, and it has no packs of recordings to save for offline use (to keep the site under GitHub's limit of 1 GB: the two copies come to about 565 MB).
  - **Anything else kept per site must be kept apart in the same way** (a new cache, `localStorage`), or the test copy will change what the stable copy relies on.
  - **First run on 2026-10-13:** both copies were published and checked from outside (each its own version, the test copy named "(test)" and without packs of recordings).
- **The build is relative** (`base: './'` in `vite.config.js`, for builds only), so the same `dist/` works in any folder. `import.meta.env.BASE_URL` is `./` there; build addresses with it, as `src/charData.js` and `src/offline.js` do, never with a leading `/`.
- **`src/serviceWorker.js`** is not part of the program. `scripts/build-offline.js` (npm's `postbuild`) copies it to `dist/sw.js` with `VERSION` (a fingerprint of the app's files) and `APP_FILES` (page, program, styles, tone table, icons, manifest) in front. It answers every request from the device's caches if it can and from the network otherwise. There is no service worker under `npm run dev`.
- **Two caches.** `app-<VERSION>` holds the app's files and is replaced with each version. `offline-data` holds the stroke data and dictionary and is kept across versions.
- **Stroke data is saved in the background, in packs.** Fetching 10,600 files one by one is too slow for a phone, so `build-offline.js` packs them 600 to a file into `dist/offline/` (18 packs, 35 MB; about 14 MB as downloaded) with a list in `offline/index.json`. `saveOfflineData` in `src/offline.js` fetches each pack and puts every file into the cache under its own address, so `loadCharData` and the service worker need to know nothing about packs. A pack's name carries a fingerprint of its contents and a finished pack leaves a mark in the cache, so an interrupted download resumes and unchanged packs are never fetched again. The dictionary is saved whole. The single files stay in `dist/` for use until the packs are in.
- **A new version waits** until the "New version ready: tap to reload" button in the footer is tapped, so the app never changes under a review. Without the tap it takes over once every tab and window of the app has been closed.
- **`navigator.storage.persist()`** keeps the browser from clearing the database to free space. It is asked for in the introduction or with a button in Settings, never by itself (see "The introduction"). How it stands is shown under "Offline use" in Settings, with the progress of the download.
- **The database at the Pages address is a different one** from the LAN dev address (see "No sync"). Moving over is Export backup there, Import backup here, once per device.
- **Icons** (`public/icons/`, since 2026-10-15): 兔 in jade green on a full moon that is also a sheet of paper (grain, the writing grid's dashed cross), in a night sky (the owner's idea, for the name 玉兔中文). The character is in AR PL UKai TW (a Kai-style font, Fedora package `cjkuni-ukai-fonts`; the owner chose it on 2026-10-13 for the earlier 字 icon). Drawn as an SVG in `scripts/icon.html` and turned into pictures by `node scripts/make-icons.js` (headless Chromium), run by hand. The maskable one keeps the moon inside the middle 80% that Android's icon shapes may cut to; `swatch.png` is the paper and 兔 alone, in dark ink, for the samples of the looks. UKai's 兔 looks like 免 at a glance, but its dot is there, inside the curve of the last stroke. Drafts, for the owner to look over with an artist: `local/icon-drafts/`. **To redo with the calligrapher's 兔** (the owner, 2026-10-16): as a browser tab's icon the night sky's dark square looks bad in their browser; not worth fixing before then.
- **`tests/browser/offline.browser.js`** builds the app, serves `dist/` from a sub-folder with a plain file server (`startBuiltApp` in the harness, like GitHub Pages), waits for everything to be saved, fakes a new version, then stops the server and checks writing, the dictionary and tone cards. It leaves `dist/` built.
- **The old address** (the move to `/yutu-chinese/` on 2026-10-15, with the name 玉兔中文; the owner's decision). The repository `BunnyApocalypse/hanzi-trainer` was renamed `yutu-chinese`, which moved the site from `.../hanzi-trainer/` to `.../yutu-chinese/`. GitHub forwards a renamed repository's own pages (code, issues, git remotes) but not its Pages site, so:
  - **Words and progress came along by themselves**: the browser keeps the database, caches, `localStorage` and long-term storage per site, not per folder. Possibly not in an app added to an iPhone's home screen, which has storage of its own; untested.
  - **A new repository `BunnyApocalypse/hanzi-trainer`** publishes only the files in `redirect/` (see its README): a page, and the same as `404.html`, that sends any address under `/hanzi-trainer/` to the same place under `/yutu-chinese/`, and a `sw.js` (published also as `test/sw.js`) in place of the app's service workers there. An installed copy keeps showing its saved app without asking for the page, so it would never see the forwarding page; but the browser still checks `sw.js` for a new version (at least daily), gets the replacement, which removes itself and sends open windows on. Its existence means GitHub no longer forwards the old repository name: remotes must point to `yutu-chinese`.
  - **`forgetOldFolder` in `src/offline.js`** deletes, once (marked in `localStorage`, `old-folder-forgotten`), the service workers registered for `/hanzi-trainer/` and what `offline-data` and `offline-audio` hold under it (about 45 MB of stroke data, dictionary and recordings; the new copy downloads its own). Never while the app is itself served from the old folder. The old `app-<VERSION>` cache is removed by the new service worker, which clears every `app-` cache but its own. Tested in `tests/browser/offline.browser.js`, which serves the app from `/yutu-chinese/`.
- **Not tested here:** installing on a real phone, and airplane mode on it. Only the owner can.
